# 隧道衬砌病害检测数据的管理平台 Demo

面向陕西省公路隧道巡检场景的二维 GIS 与 AI 病害诊断交互原型。项目使用 Vue 3、Vite 和 Leaflet 构建，采用“单页、单图、单入口”的设计，将查询、诊断、分级处置和档案全部融合到地图工作台，重点验证“隧道一张图—图片上传—病害识别—分级诊断—处置建议—病害归档”的完整业务闭环。

## 已实现能力

- 陕西省边界、主要高速公路示意路网和 33 条隧道实体上图
- 隧道名称、路线、状态和空间赋位等级筛选
- 点击节点查看实体属性、空间精度、健康状态与历史病害
- 上传 JPG、PNG、WebP 图片并绑定指定隧道
- 模拟影像质检、病害检测、几何量化、分级和处置建议流程
- 存在病害、未发现病害、需要人工复核三种结果分支
- 识别置信度与病害严重等级分开展示，避免概念混淆
- 当前隧道检查/病害记录在底部上下文栏展开，不跳转独立模块
- AI诊断保存后即时写入当前隧道的前端演示档案

## 界面约束

- 仅使用二维底图，不加载 Cesium、SuperMap 或三维场景
- 配置 `VITE_TIANDITU_TK` 后使用天地图影像与中文注记；未配置 Key 时自动回退到 EOxCloudless Sentinel-2 影像，避免演示白屏
- 顶部按参考界面恢复“智能诊断 / 模型中心”双模块导航，并保留运行时间和管理员区域
- 左侧 AI 诊断、中心 GIS 地图、右侧隧道档案与底部记录栏始终围绕同一隧道上下文联动
- 视觉语言参考随附 GIS 交付基座的专业工程工作台，但不复制示例页面和业务内容

> 天地图 Key 只通过部署环境变量注入，不写入源码。EOxCloudless 2025 仅作为未配置 Key 时的非商业 Demo 备用图层，界面保留服务署名。正式使用前应根据服务条款确认配额与授权范围。

## 数据说明

隧道基础属性来自 `陕西省隧道地理实体数据集_空间赋位初版.xlsx`。其中 4 条记录具有来源表中的代表点/洞口坐标；其余记录根据路线、桩号或行政区信息配置为 Demo 示意位置，并在界面中以空心节点和精度提示明确区分。示意坐标不会回写或覆盖原始数据。

地图中的健康指数、病害数量、诊断记录、算法指标和处置状态均为交互演示数据，不代表任何隧道的实际技术状况。

## 本地运行

```bash
npm install
npm run dev
```

如需启用天地图，先复制环境变量示例并填写浏览器端 Key：

```bash
cp .env.example .env.local
npm run dev
```

生产构建：

```bash
npm run build
```

## 静态部署

GitHub 仓库可直接导入腾讯云 EdgeOne Pages、Cloudflare Pages、Vercel 或 Netlify：

- 安装命令：`npm ci`
- 构建命令：`npm run build`
- 输出目录：`dist`
- 环境变量：`VITE_TIANDITU_TK=<天地图浏览器端Key>`

部署完成后，将正式访问域名补到天地图控制台的域名白名单。预览域名经常变化时，可先绑定一个固定自定义域名，再填写该域名。

## 后续算法接入

前端正式接入现有识别算法时，建议由 Java 平台服务提供统一任务接口，算法服务只负责推理，规则服务负责分级。统一返回病害类型、几何区域、置信度、测量值、严重程度、规则依据、建议动作和模型版本，避免前端与单一模型耦合。接口建议见 `docs/algorithm-adapter-contract.md`。
